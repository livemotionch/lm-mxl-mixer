# 10-bit v210: native kernels

An MXL vision mixer has to keep 10 bits from v210 input to v210 output. v210 is
three 10-bit samples per 32-bit word, in UYVY order (`Cb Y Cr Y …`). The
operations that treat every sample alike, which are most of what a vision mixer
does (a cut, a mix at one level, a fill, a hard wipe that is a copy of a span),
run on the words without unpacking them. Only spans that need a level per pixel
(keys, soft wipes) or filtering (DME boxes), or a move by a number of pixels
that isn't a multiple of 3, are unpacked, to 16-bit samples, and only the
48-pixel runs that aren't fully transparent.

The kernels are hand-written: unpack and pack in SSSE3 and AVX2 (4 or 8 words
per round: fields masked and shifted into 32-bit lanes, paired into 16-bit
lanes, ordered with byte shuffles), the in-place word mix with `pmulhrsw`
(fields 0 and 2 in the two 16-bit halves of a lane, field 1 in another
register; `d + ((s − d)·a + 2¹⁴) >> 15` is exactly `pmulhrsw` for 10-bit
differences), 16-bit blends likewise. Scalar twins exist for each and the tests
compare them.

## Scaling

`src/compositor/scale10.rs`, `render10.rs`, `simd10.rs`:

- Source rows are unpacked straight into Y, Cb, Cr planes (`unpack_planar`,
  SSSE3: one 6-pixel block per step).
- Vertical sums one source row after the other into `u32` rows that stay in L1
  (vectorised), the next source row prefetched; normalised to Q5 `u16`.
- Horizontal: 8 outputs at a time, a 32-bit gather fetches the two neighbouring
  Q5 samples of each output, `pmaddwd` multiplies them by the pair of weights,
  two taps per step; the sum is scaled in floating point. A scalar twin
  computes the same.
- Whole-number boxes (both ways, kx·ky ≤ 32): `u16` row sums, then `phaddw`
  folds for widths 1, 2, 4, 8 and `pmulhrsw` by `round(32768 / (kx·ky))`;
  other widths take the filter with weights of 1.
- Decimation: downscales of 7.5:1 or more read every n-th row from the middle of
  each block (`render::vertical_step`, `MIXER_DECIMATE=0` turns it off), in the
  10-bit renderer and for the preview's thumbnails.
- The 8-bit engine (preview mosaic) reads v210 words into bytes in one pass
  (fields in 16-bit lanes, rounded, `packuswb`, one shuffle; SSSE3 and AVX2).

## Where the time goes

1080p, one core of the test VM (AMD EPYC Genoa, AVX2), ms per frame, best /
average (`cargo run --release --example bench10`):

| Scene | ms per frame |
| --- | --- |
| cut | 0.12 / 0.13 |
| mix | 0.46 / 0.48 |
| dip (a colour over a frame) | 0.62 / 0.65 |
| hard wipe (clip rectangle) | 0.15 / 0.15 |
| soft iris wipe (a level per pixel) | 3.5 / 4.1 |
| push (moved by 768 px: words line up) | 0.40 / 0.46 |
| push (moved by a number of pixels that isn't a multiple of 3) | 0.54 / 0.62 |
| cut + DSK lower third (v210a key) | 1.45 / 1.53 |
| cut + full-screen luma key | 1.68 / 1.84 |
| cut + PiP 1:4 (box filter) with border | 0.77 / 0.84 |
| cut + PiP 0.3 (fractional size) with border | 1.32 / 1.42 |
| quad split, 4 × 1:2 boxes, one source | 2.84 / 3.27 |
| grid of 4 different sources (1:2) | 3.51 / 4.42 |
| grid of 8 different sources | 8.04 / 8.77 |
| grid of 16 different sources (1:4) | 12.9 / 14.0 |
| mix + PiP 0.3 + DSK | 3.07 / 3.49 |
| preview mosaic frame, 8 sources (8-bit: PVW, PGM, source tiles) | 2.33 / 2.53 |
| preview mosaic frame, 16 sources (decimated thumbnails) | 1.93 / 2.08 |

- Copies, mixes and hard wipes run at memory speed.
- A scaled source costs about 0.65 ms at whole-number ratios (1/2, 1/3, 1/4:
  box sums without weights) and about 1.2 ms at other sizes; the UI's DME
  presets use whole numbers. The grid of 16 different sources is bound by
  reading 88 MB of frames from memory.
- Keys cost what their visible area costs: a key row at the key's start is
  skipped from its raw words, transparent 48-pixel runs aren't read, opaque runs
  are copied.
- Soft wipes compute the pattern per pixel (vectorised per row) and blend the
  edge; the hard rectangular wipes are clip rectangles (copies).

## Accuracy

`src/compositor/tests10.rs` draws random layouts (unscaled and scaled sources,
crops, moves that don't line up with words, opacity, luma and linear keys, clip
rectangles, wipe masks, fills, borders, odd canvas widths) and compares every
sample with a slow reference that draws each layer whole, bottom-up, with
floating-point filter weights: within ±1 for unscaled layers, ±2 scaled (±4
with a steep linear key on a scaled box, where the key's gain amplifies the
weights' rounding); a cut is the source's bytes; decimated boxes equal the
reference drawn from the rows read. The 10-bit path uses weights in 1/1024
(`Table::with_total`).
